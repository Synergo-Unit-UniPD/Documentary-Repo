\section{Casi d'Uso}

\subsection{Attori}
\begin{itemize}
	\item \textbf{Utente}: Attore\textsubscript{G} primario $\rightarrow$ Rappresenta l'utilizzatore finale che interagisce con l'interfaccia dell'applicazione. 
    In base al capitolato e ai verbali esterni, il profilo di riferimento è un utente giovane, tipicamente uno studente, che utilizza l'applicazione per prendere appunti e desidera supporto nell'elaborazione tramite LLM (VE-5.3).
	\item \textbf{LLM (Large Language Model\textsubscript{G})}: Attore secondario (sistema esterno) $\rightarrow$ Fornisce i servizi di analisi e generazione testo tramite API compatibile con lo standard OpenAI. I modelli di riferimento sono Gemma, ChatGPT-OSS e Qwen, messi a disposizione dall'azienda proponente (VE-1.1).
\end{itemize}

% UC1 - Scrittura di testo nell'editor
\hypertarget{uc1}{}
\subsubsection{UC 1: Scrittura testo nell'editor}

% use case diagram
\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\textwidth]{scrittura_nota.png}
    \caption{UC 1 – Scrittura di testo nell'editor}
\end{figure}

\begin{itemize}
    \item \textbf{Attore Principale}: Utente
    \item \textbf{Precondizioni}: L'editor è attivo ed è presente una nota aperta nell'editor.
    \item \textbf{Scenario Principale\textsubscript{G}}:
    \begin{enumerate}
        \item L'utente posiziona il cursore nell'area di testo.
        \item L'utente inserisce testo tramite tastiera.
        \item Il sistema aggiorna in tempo reale l'area di testo con il contenuto inserito.
        \item Il sistema aggiorna l'anteprima renderizzata, se la modalità di visualizzazione attiva lo prevede.
    \end{enumerate}
    \item \textbf{Postcondizioni}: Il testo inserito è visibile nell'editor e, ove applicabile, nell'anteprima renderizzata.
    \item \textbf{Trigger}: L'utente vuole inserire o modificare i contenuti testuali della nota.
\end{itemize}

\subsection{Macroarea 2 — Interazione AI (LLM)}
\textit{Elaborazione del testo tramite modelli linguistici e gestione degli output generati.}

\noindent
Per tutte le funzionalità basate su LLM, il sistema visualizza durante l'elaborazione
una finestra modale contenente un indicatore di caricamento e rende disponibile
un comando di interruzione. Al completamento dell'elaborazione, il sistema
visualizza la proposta generata in una finestra modale dedicata, dalla quale
l'utente può accettarla, rifiutarla o richiederne la rigenerazione. Nessuna
proposta viene applicata automaticamente al contenuto della nota.

% Funzionalità opzionali di persistenza remota
% --------------------------------------------------------------------------

\noindent
Le funzionalità opzionali di persistenza remota utilizzano un database
PostgreSQL gestito dal sistema e configurato dagli amministratori
dell'applicazione mediante i parametri di connessione previsti
dall'ambiente di esecuzione. L'utente non configura direttamente il database
né seleziona un servizio cloud esterno. Alla creazione dell'account, il sistema
associa all'utente uno spazio logico personale nel quale vengono memorizzate
le relative note. Le note sono associate all'account autenticato e non sono
accessibili agli altri utenti.

% UC150 - Registrazione utente 
\hypertarget{uc150}{}
\subsubsection{UC 150: (Opzionale) Registrazione utente}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\textwidth]{registrazione_utente.png}
    \caption{UC 150 – Registrazione utente}
\end{figure}

\begin{itemize}
    \item \textbf{Attore Principale}: Utente
    \item \textbf{Precondizioni}: Il sistema è avviato, il servizio di persistenza remota è disponibile e l’utente non è autenticato nel sistema.
    \item \textbf{Scenario Principale}:
    \begin{enumerate}
        \item L'utente attiva la funzione di registrazione.
        \item Il sistema mostra il modulo di registrazione.
        \item L'utente inserisce l'indirizzo email da associare all'account.
        \item L'utente inserisce la password scelta.
        \item L'utente reinserisce la password per confermarla.
        \item Il sistema verifica la validità dell'indirizzo email, la corrispondenza
        tra le password inserite e il rispetto dei requisiti previsti per la password.
        \item Il sistema crea il nuovo account.
        \item Il sistema associa all'account uno spazio logico personale nel database remoto.
        \item Il sistema conferma l'avvenuta registrazione.
    \end{enumerate}
    \item \textbf{Postcondizioni}: È stato creato un account associato
    all'indirizzo email inserito e al relativo spazio logico personale
    nel database remoto.
    \item \textbf{Trigger}: L'utente desidera creare un account per accedere alle funzionalità di persistenza remota.
    \item \textbf{Estensioni}:
    \begin{itemize}
        \item \hyperlink{uc150.1}{UC 150.1: Visualizzazione errore email registrazione}
        $\rightarrow$ Condizione: l'indirizzo email non è valido oppure è già associato
        a un account al passo 6.
        \item \hyperlink{uc150.2}{UC 150.2: Visualizzazione errore password registrazione}
        $\rightarrow$ Condizione: le password non coincidono oppure la password non
        rispetta i requisiti previsti al passo 6.
    \end{itemize}
\end{itemize}
