\section{Documentazione}

La documentazione prodotta dal gruppo \textit{Synergo Unit} è organizzata per garantire
coerenza, tracciabilità e accessibilità. Essa è suddivisa in documentazione gestionale e
documentazione tecnica, secondo la classificazione prevista dal regolamento del progetto
didattico.

\subsection{Template e convenzioni}

Per assicurare uniformità nella produzione documentale, il gruppo adotta le seguenti
convenzioni:

\begin{itemize}
    \item \textbf{Nomi dei file}: tutti in minuscolo, con ``\_'' come separatore
    (es.: \texttt{verbale\_interno\_2026\_03\_13.tex}).

    \item \textbf{Titoli di sezioni e sotto-sezioni}: stile Title Case\textsubscript{G} per ogni livello
    (es.: ``Lettera Di Presentazione'').

    \item \textbf{Pedice G\textsubscript{G}}: applicato solo alla prima occorrenza di un termine presente nel
    glossario (es.: Termine\textsubscript{G}).

    \item \textbf{Decisioni}: identificate tramite codice \texttt{VI-y.x\textsubscript{G}}, dove \texttt{y} è il numero del
    verbale e \texttt{x} il numero progressivo della decisione.

    \item \textbf{Task\textsubscript{G}}: identificati tramite codice \texttt{T-y.z\textsubscript{G}}, dove \texttt{y} è il numero del
    verbale di origine e \texttt{z} il numero progressivo del task. L’ordinamento segue:
    scadenza, decisione di riferimento, codice incrementale.
\end{itemize}

\subsection{Struttura Documenti}

\subsubsection{Documentazione Gestionale Interna}

\begin{itemize}
    \item \textbf{Norme Di Progetto\textsubscript{G}}: definiscono processi, convenzioni e strumenti adottati dal gruppo.
    \item \textbf{Verbali Interni}: documentano discussioni, decisioni e attività operative. Non
    includono changelog: viene pubblicata solo la versione approvata.
    \item \textbf{Glossario}: raccoglie i termini specialistici utilizzati nella documentazione.
\end{itemize}

\subsubsection{Documentazione Gestionale Esterna}

\begin{itemize}
    \item \textbf{Verbali Esterni}: documentano incontri o comunicazioni con aziende o docenti.
    \item \textbf{Valutazione Dei Capitolati\textsubscript{G}}: documento comparativo che motiva la scelta del capitolato.
    \item \textbf{Dichiarazione Degli Impegni\textsubscript{G}}: contiene scadenza prevista, preventivo dei costi\textsubscript{G},
    assegnazione ore e ruoli, rischi attesi e impegni formali del gruppo.
\end{itemize}

\subsubsection{Documentazione Tecnica}

Nella fase pre-candidatura\textsubscript{G} non è presente documentazione tecnica, né interna né esterna.
Essa verrà introdotta solo dopo l’aggiudicazione del capitolato (es.: Analisi Dei Requisiti,
Specifica Architetturale, Manuale Utente).

\subsection{Ciclo di Vita Documentale}

\begin{enumerate}
    \item \textbf{Stesura}: il redattore compila il contenuto utilizzando il template approvato.
    \item \textbf{Revisione\textsubscript{G}}: il verificatore controlla struttura, coerenza e correttezza.
    \item \textbf{Pubblicazione}: il documento viene caricato nella repository\textsubscript{G} con la versione aggiornata.
    \item \textbf{Approvazione}: la versione pubblicata viene approvata dal Responsabile.
    \item \textbf{Ingresso in baseline\textsubscript{G}}: la versione approvata diventa stabile.
\end{enumerate}

\textbf{Nota:} I verbali non prevedono versionamento incrementale: viene pubblicata direttamente la
versione approvata.

\subsection{Strumenti di Documentazione}

La documentazione è redatta in \LaTeX{} e gestita tramite Visual Studio Code, configurato con
l’estensione LaTeX Workshop per la compilazione automatica dei PDF. 

La struttura dei documenti segue un template condiviso composto da:

\begin{itemize}
    \item una cartella principale con il nome del documento;
    \item file separati per le sezioni (frontespizio, registro modifiche, contenuti);
    \item una cartella \texttt{shared/} contenente loghi e configurazioni comuni;
    \item uno script Python  contenuto in \texttt{python\_glossary\_automation/} che applica automaticamente il pedice G\textsubscript{G} alla prima occorrenza dei termini del glossario.
\end{itemize}

\subsection{Gestione della Configurazione Documentale}

La gestione della configurazione documentale avviene tramite GitHub:

\begin{itemize}
    \item ogni membro utilizza un branch\textsubscript{G} personale;
    \item le modifiche vengono integrate tramite pull request\textsubscript{G};
    \item la struttura delle cartelle riflette la classificazione dei documenti;
    \item la versione approvata di ogni documento è quella presente nel branch \texttt{main}.
\end{itemize}

\subsection{Versionamento}

Il gruppo adotta il Semantic Versioning\textsubscript{G} a tre cifre: \textbf{vX.Y.Z}.

\begin{itemize}
    \item \textbf{X (Major)}: rilasci ufficiali o cambiamenti strutturali profondi.
    \item \textbf{Y (Minor)}: aggiunta o modifica significativa di contenuti.
    \item \textbf{Z (Patch)}: correzioni ortografiche o modifiche non semantiche.
\end{itemize}
